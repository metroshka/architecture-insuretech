## Нагрузочное тестирование — Task2

Тест выполнен в локальном кластере Minikube `insuretech` с включённым metrics-server. Использован исходный образ `ghcr.io/yandex-practicum/scaletestapp:latest`.

- Начальное количество реплик — **1**, максимум HPA — **10**.
- Запрос памяти контейнера — **20Mi**, лимит — **30Mi**. Целевая утилизация HPA — **80% от запроса памяти**, то есть 16Mi.
- Нагрузка увеличена до **500 виртуальных пользователей**; сценарий выполняет `GET /` с паузой от 1 до 5 секунд.
- В [журнале HPA](Task2/results/hpa-after-test.log) зафиксировано последовательное увеличение количества реплик до **7**.
- По [статистике Locust](Task2/results/locust_stats.csv) выполнено **66 752 запроса**, из них **74 завершились ошибкой** — около 0,11%.
- [Журнал перезапусков](Task2/results/pod-restarts.log) содержит два перезапуска контейнеров с причиной `OOMKilled`.

Результаты подтверждают работу автомасштабирования. При этом в тесте сохранялись ошибки запросов и случаи превышения лимита памяти. Подробная динамика находится в [журнале масштабирования](Task2/results/scaling.log) и [истории Locust](Task2/results/locust_stats_history.csv).

Особенности подготовки исходного образа для Minikube на Mac с ARM описаны в комментариях к [Deployment](Task2/deployment.yaml).

## Обозначения паттернов — Task4

Библиотека обозначений паттернов отказоустойчивости из задания недоступна; недоступность подтверждена куратором. На схеме используются текстовые обозначения **R1 — Rate Limiting**, **R2 — Circuit Breaker**, **R3 — Retry** и **R4 — Timeout**. Их применение и поведение при сбоях описаны на страницах схемы.

Task1, Task3 и Task4 содержат проектные решения. Значения RTO/RPO, нагрузка ОСАГО в 2500 одновременных пользователей и срок ожидания 60 секунд требуют проверки при реализации; результаты такого тестирования в проекте не заявляются.
